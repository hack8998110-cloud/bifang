# 毕方反馈收集指南

毕方开源版不会自动上传用户数据。要判断它是否真的有用，必须主动收集反馈。

## 推荐反馈路径

### 1. 私域客户

使用：

```text
templates/user_feedback_record.md
```

只把其中的“客户简版反馈”发给客户，内部复盘部分自己填。

### 2. GitHub 开源用户

让用户提交 Issue：

- 试用反馈：`.github/ISSUE_TEMPLATE/trial_feedback.md`
- Bug 报告：`.github/ISSUE_TEMPLATE/bug_report.md`

### 3. 你代跑的客户

每个客户单独建一份记录：

```text
user_tests/日期_行业_账号名.md
```

记录：

- 原始输入
- 毕方输出
- 客户反馈
- 是否愿意试拍
- 是否进入下一步

## 反馈最重要的 7 个问题

1. 用户是否看懂“客户真正想看什么”？
2. 用户是否认可“今天先拍这几条”？
3. 用户是否愿意按其中一条去拍？
4. 用户是否能提供对应证据素材？
5. 用户觉得哪一段最有用？
6. 用户觉得哪一段没用或看不懂？
7. 用户是否愿意继续补素材、写脚本或发布测试？

## 什么反馈值得进入版本

不要因为一个用户说不懂就改核心规则。

建议标准：

- 1 次出现：记录。
- 2 次出现：检查模板或 QUICKSTART。
- 3 次以上出现：考虑进入测试用例或核心 skill。

优先级：

1. 安装/首次使用卡点：优先改文档和验证脚本。
2. 问法不清楚：优先改 QUICKSTART。
3. 试用交付太重：优先改模板。
4. 行业判断反复跑偏：增加测试用例。
5. 同类判断错误出现 3 次以上：再考虑改核心 skill。

## 不建议收集什么

除非客户明确同意，不要公开：

- 私信截图
- 客户姓名
- 真实销售数据
- 未脱敏账号链接
- 医疗、法律、财税、教育等敏感案例细节

## 反馈后的处理

每 10 个真实用户做一次总结：

```text
1. 哪些行业最容易用懂？
2. 哪些行业最容易跑偏？
3. 用户最认可哪类输出？
4. 用户最看不懂哪类输出？
5. 有几个人愿意进入第一条脚本？
6. 有几个人真实发布？
7. 哪些问题重复出现 3 次以上？
```

如果 10 个用户里至少 7 个能看懂、5 个愿意选一条试拍、3 个真实发布测试，可以考虑把 `v0.2-rc` 升级为正式版。
