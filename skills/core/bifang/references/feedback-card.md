# 毕方反馈卡

用户指出结果答错、跑偏、重复提问、不可拍或不好用时使用。先修正当前交付，再把问题整理成可回归验证的记录；不要用记录反馈代替解决问题。

## 固定字段

```yaml
user_request: 用户原始需求
task_stage: 方向 / 选题 / 脚本 / 审核 / 改稿 / 拆片 / 复盘
observed_output: 本轮实际做了什么
user_feedback: 用户指出哪里不对，尽量保留原话
failure_type: 路由错误 / 重复提问 / 判断跑偏 / 不可拍 / 证据不足 / AI味 / 改丢锚点 / 审核漏放 / 复盘误判 / 其他
expected_behavior: 修正后应当发生的可观察行为
regression_input: 可复现问题的最小输入
status: 待修正 / 已修正待验证 / 已进入回归
```

## 处理顺序

1. 用一句话确认具体问题，不写长篇解释。
2. 立即重做当前任务中失败的部分，复用仍然有效的状态，不让用户重讲。
3. 输出修正版后，再生成反馈卡；宿主支持文件时存入项目的 `bifang-feedback/`，否则留在当前对话供后续整理。
4. `expected_behavior` 必须可以测试，例如“用户回复第二个后直接成稿，不重新询问行业”，不能只写“回答更好”。
5. 同一问题连续出现时更新原卡并增加实例，不重复堆砌相同规则。
