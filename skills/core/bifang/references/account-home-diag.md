# 主页诊断卡（粘贴也能用）

用户丢来主页简介、近期作品标题/口播摘要、或一段账号描述时用。  
**不要求**先有后台数据或真实链接；有链接且用户允许再另议（本页默认粘贴输入）。

与 [review-card.md](review-card.md) 衔接：本卡偏「主页+片单快诊 + 2–4 周方向条」；review-card 偏「已有作品/数据问题时的人话三句复盘」。二者都用「保留/停止/重写」，**不互相发明第二套黑话**。  
方向条细则可另见 [direction-strip.md](direction-strip.md)（内容与本节「后续方向条」一致，免重复维护时可只改一处并互指）。  
结果要**交给老板/客户拍板** → 压成 [agency-deliverable-card.md](agency-deliverable-card.md)（无评分、无模块名）。

原则借鉴（非原文）：GitHub `inklate/social-skills` social-audit（粘贴证据、说清不可知、最大杠杆优先）；HBVD review（事实/假设/不能下的结论）；SkillHub 账号体检（**不借**打分表，只借「数据覆盖度要声明」）。详见 [borrow-from-peers.md](borrow-from-peers.md)。

## 输入（任一即可开诊）

| 类型 | 例子 | 够不够 |
|---|---|---|
| 主页简介粘贴 | 昵称+简介+置顶说明 | 可诊人设/CTA；片型弱 |
| 近期作品列表 | 标题或口播摘要 5–15 条 | 可诊片型/证据癖好 |
| 抖音/主页链接 | 用户丢链接且可试读 | 先试读；失败走「诊失败回退」 |
| 用户口述 | 「我们全是晒货+活动价」 | 可诊，须标假设 |
| 带少量数据 | 「这条播了 xx，那条不行」 | 只写用户给的数，不编 |

信息不够时：**先诊能诊的**，文首用一行写清「还缺什么会误判」；最多补问 1–3 个。不要问卷式画像。

## 固定输出（对用户可见）

```text
（可选）输入覆盖：简介✓/作品列表✓或✗/数据✗ —— 缺什么不能乱下结论

人设是否清楚：（一句：外人 3 秒知不知道你帮谁做什么选择）
片型是否单一：（一句：最近是不是同一种片；点名证据）
证据是否只会晒货：（一句：有没有过程/标准/边界，还是只堆货与形容词）
CTA：（一句：主页/片尾让人干什么；是否过硬或空洞）

保留 / 停止 / 重写：
- 保留：…
- 停止：…
- 重写：…

后续 2–4 周方向条：（3–5 条，选题级一句话，不是长方案）
1. …
2. …
3. …

下一步：（唯一：回方向条编号写成稿 / 补贴 N 条标题 / 先改编某条口播；可附一句「要的话我帮你排成两周」——用户未要则不甩日历）
```

回执：`毕方已接管｜本次完成：复盘`（主页诊断属复盘/诊断族；勿对用户说模块名）。

## 硬规则

1. **每句判断要能指回用户材料**（引用简介原句或标题）。指不回就标「假设」。
2. **不编播放、成交、限流原因**；无数据写「数据未知，不归因算法」。用户口述或粘贴的**公开粉丝/作品数**可以引用，并标明「公开量级/口述」；不得写成后台分析结果。
3. **不主动甩六维/健康分/总分表**（作者禁自嗨评分）。
4. **片型单一**与「支柱塌缩」用人话说：如「近 10 条里 8 条都是活动价口播」。
5. **晒货判定**：只有成品图/价格/口号、没有可核对过程或标准 → 点名「只会晒货」。
6. **方向条**必须是选题级短句（可直接进 [topic-card.md](topic-card.md) 极简层），禁止一次甩几十条；**默认禁止**主动甩按天长表。用户点名日历 → [direction-calendar-14d.md](direction-calendar-14d.md)。
7. 高风险行业方向条仍受 [high-risk.md](high-risk.md) 约束。
8. 扫黑话：[banned-corp-jargon.md](banned-corp-jargon.md)。

## 与 review-card 怎么分工（勿打架）

| 场景 | 用谁 |
|---|---|
| 只有「最近不行了/老片有问题」几句 | [review-card.md](review-card.md) 三句即可 |
| 贴了简介 + 作品列表，问「账号方向怎么调」 | **本卡**（含方向条） |
| 只口述「像素材号/私信不来」几句、无片单 | [review-card.md](review-card.md)；若随后补贴标题列表，升级本卡补方向条 |
| 本卡出完后用户说「先复盘主要矛盾」 | 可再压成 review-card 三句，方向条保留在下一步里 |
| 用户只要 3 条选题、不要诊断 | 走选题极简层，不硬上本卡 |
| 已有方向条且用户要排两周/日历 | [direction-calendar-14d.md](direction-calendar-14d.md)；仍不主动评分、不分镜 |
| 结果要给老板/客户拍板 | [agency-deliverable-card.md](agency-deliverable-card.md)；字段从本卡压出 |
| 链接试读失败 / 只读到简介 | 见下节「诊失败回退」；禁止假装读过作品 |
| 诊失败后用户补来 8–12 条标题 | 见「补标题→重诊」；必须刷新片型/晒货 |
| 主页诊/重诊后说「今天拍哪条 / 先写第一条」 | 见「诊后今天先拍」；直出口播，不必先走代运营壳 |

保留/停止/重写字段两边同义：本卡可写细一点，但不发明「飞轮/势能/心智」替代词。


## 诊失败回退（链接可读简介、作品区失败）

用户丢来**抖音主页 / 账号链接**时：允许试读公开页。  
若出现下列任一情况，**立刻走回退**，不要硬诊片型：

- 作品区加载失败 / 「服务异常」/ 空白
- 登录墙、验证码、地区限制
- 只能读到昵称+简介，标题列表为空或乱码
- 抓取超时、页面结构变化导致读不到作品

### 回退硬规则

### 标准话术模板（须原样骨架 · SKILL 可见）

用户可见回复**第一屏**用此骨架（可换行业词，不可删「覆盖度 / 未知 / 要标题」三件套）：

```text
输入覆盖：简介□ / 作品列表✗（____）/ 数据✗
—— 片型与晒货：未知。我不会假装看过你的作品。

人设：（仅据简介；不可据则写未知）
片型：未知
证据是否只会晒货：未知
CTA：（简介侧粗判或未知）

保留 / 停止 / 重写：
- 保留：…（待作品确认）
- 停止：待标题列表确认前，不下死结论
- 重写：待确认

方向条：暂缓 / 或 3 条标「假设，待标题确认」

下一步（唯一）：请粘贴最近 8–12 条作品标题，或发作品列表截图（能看清字即可）。
```


1. **文首写清覆盖度**：例如「输入覆盖：简介✓ / 作品列表✗（作品区服务异常）/ 数据✗」。
2. **禁止假装读过作品标题**：不得编造「近 8 条多为××」；片型、晒货标必须写 **未知**。
3. **立刻要材料**：请用户贴 **8–12 条**近期作品标题，或作品列表截图（文字可辨即可）。
4. **能诊的先诊**：简介可读 → 可写人设一句、CTA 粗判；保留/停止/重写里与片型相关的项标「待标题确认」。
5. **方向条**：可给 3–5 条**假设向**选题，但须标明「待标题列表确认后再收窄」；或先不出方向条，唯一步只要标题。
6. **不编播放/限流**；不甩评分表。
7. 用户要交老板 → 可用 [agency-deliverable-card.md](agency-deliverable-card.md) 骨架，片型/晒货仍标未知。

## 补标题→重诊（0.3.22）

场景：上一轮已走「诊失败回退」（片型/晒货未知、要过标题）；本轮用户贴来 **8–12 条**作品标题（可带简单播放/点赞口述，有则用、无则不编）。

### 触发条件

| 条件 | 动作 |
|---|---|
| 标题条数 ≥8（或截图可辨 ≥8） | **必须重诊**；刷新片型与晒货 |
| 标题 5–7 条 | 可粗诊并标明「样本偏少」；仍刷新片型/晒货，勿写未知 |
| 标题 <5 或看不清 | 再要补到 8；片型/晒货可暂「样本不足」，**禁止**装成完整片单结论 |
| 用户说「就这些」且 <5 | 按已有条数诊，文首写「仅 N 条，片型置信偏低」 |

### 硬规则

1. **标题已够仍写「片型未知 / 晒货未知」= 违规。** 必须据标题点名片型（如「近 10 条里 7 条课表干货」）与晒货判定。
2. **保留原简介结论**：人设/CTA 若简介侧已诊过，默认沿用；仅当标题与简介明显冲突时改写人设并点名冲突。
3. **用标题证据重写**保留/停止/重写与方向条：可微调，**勿推倒重来**——除非标题与简介冲突（例：简介写代运营、标题全是个人生活 vlog）。
4. **文首一行**：`已用你补的 N 条标题重诊。`（N=实际条数）
5. **不编播放/限流**；用户口述的数可引用并标「口述」。
6. **无评分表**；扫黑话。
7. 重诊后唯一步优先：回方向条编号成稿 / 「今天先拍」直出 → 见下节。

- 保留：…（指回简介或标题）
- 停止：…（指回标题堆叠）

## 诊后「今天先拍」直出可拍短稿（0.3.22）

场景：主页诊断或「补标题重诊」**已完成**（方向条已出）；用户说「今天拍哪条 / 先写第一条 / 直接给我可拍的 / 今天先拍」——**不必**先走代运营交付壳编号。

### 触发说法

| 用户说法 | 默认动作 |
|---|---|
| 「今天拍哪条」「先写第一条」「直接给我可拍的」 | 取方向条 **第 1 条** → 直出可拍短稿 |
| 「今天拍第 2 条」「写 3」 | 取对应编号 |
| 只有诊断、尚无方向条 | 先补 3 条方向条再问编号；或一句话确认后按第 1 条写 |
| 证据不够成稿 | 出口播骨架 + 补拍清单，不假装可拍 |

### 与代运营壳「回编号→可拍」的关系

两条入口**等价成稿**，粒度对齐 [script-45s.md](script-45s.md) / [agency-deliverable-card.md](agency-deliverable-card.md)「回编号成稿」：

| 入口 | 壳要不要 |
|---|---|
| 主页诊/重诊后「今天先拍」 | **可省壳**；直接成稿 |
| 老板可读卡上回复编号 | 走代运营壳回编号成稿 |

交叉指针：本页直出 ↔ agency「回编号成稿」；对老板仍勿说模块名。

### 硬规则
