# 同业借鉴清单（去 AI 感 · 舒服交付）

来源：SkillHub / GitHub 同类型短视频脚本技能对照（调研笔记，非抄袭原文）。  
用途：后期改毕方交付标准时对照；**先记原则，改文件前再开任务。**

## 必须守住（毕方已有）

- 商业判断先于模板：谁 / 决策 / 证据 / 成交理由
- 证据闸门：不够不成稿
- 薛辉脚本类型 + 爆款元素（后台约束）
- 单一下一步；不堆工作台菜单

## 建议吸收（对标结论）

### 1. 成稿后强制「口语化 / 去 AI」一关
对标：花叔 `huashu-script-polish`、入行365 humanizer。  
标准：
- 用户可见口播必须说得出口：短句为主（单句宜 ≤20 字），逗号长句拆开
- 删书面腔与黑话（赋能、闭环、抓手、赋能式排比、正确但没信息的空话）
- 大声读一遍会卡顿处必须改
- 字段名（观看任务、证明任务、选题卡等）不对小白展示；类型/看点可用白话一句带过

### 2. 可见层只要人话；结构放后台
对标：`short-video-script-skill`（轻量拍摄建议默认）、`human-best-video-director`（要结构不强塞逐字稿）。  
标准：
- 默认交付：口播全文 → 拍什么三五句 → 机位一句 → 别拍错
- 完整分镜表 / 评分表 / 多维字段：仅用户明确要求时展开

### 3. 口播密度可验收
对标：`shortvideoplan`（字数÷秒数）。  
标准：
- 按平台目标时长估字数；超密则当场给压缩版，不把问题留给用户
- 宁可短一句，不堆同义复述

### 4. 少问、推断并标明假设
对标：`human-best-video-director`。  
标准：
- 信息够直接做；缺口最多 1–3 个会影响结果的问题
- 平台等可默认时写明假设（如平台假设：抖音）

### 5. 防幻觉与合规仍与「人话」并行
对标：`shortvideoplan` 违禁词 / 无证据降级。  
标准：
- 无案例不编案例；效果承诺无来源则改写为标准/流程/边界
- 人话不等于随便承诺

## 明确不照搬

- 六维评分、总分、对外「爆款公式打分」堆表（易 AI、易自嗨）
- 一次甩几十个选题掩盖判断
- 把所有人口吻磨成同一种「通用人类腔」（保留行业/人物语气）

## 验收口诀（给后期改稿用）

> 后台有骨架，前台像人说；读得顺、拍得到、没有编的数。
