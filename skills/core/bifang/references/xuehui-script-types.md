# 脚本类型（四选一）

对用户可称「脚本类型」，不要堆模块名或内部来源名。

**硬规则：先做商业判断（谁 / 决策问题 / 证据 / 成交理由），再选类型。类型只决定讲法骨架，不能替代判断。**

成稿前必须四选一，并在交付里写明。

---

## 1. 教知识

**何时用**：用户卡在「怎么判断 / 怎么做对」；你有可讲清的标准、步骤或检查法；内容主功能偏信任或生产。

**结构骨架**：
1. 点名人群（谁、什么场景）
2. 易错判断（常见错法或假标准）
3. 2–3 个可执行动作
4. 怎么检查（拍得到、听得懂的验收标准）

**注意**：动作必须可拍、可核对；不要只讲概念。

---

## 2. 晒过程

**何时用**：现场、制作、服务流程本身就是证据；需要用「看见过程」建立信任或转化。

**结构骨架**：
1. 起因（为什么开始 / 客户遇到什么）
2. 经过（关键步骤，可拍）
3. 结果（可核对的结果或半成品）
4. 穿插情绪 / 冲突 / 反差片段（服务观看，不能代替证明）

**注意**：过程镜头要同时扛观看任务与证明任务。

---

## 3. 聊观点

**何时用**：行业有主流说法，你要纠偏或立标准；适合获客与信任，观点必须落到场景与行动。

**结构骨架**：
1. 点名人群
2. 反常识（一句刺破旧判断）
3. 场景证明（可拍事实或案例边界）
4. 行动标准（听完知道怎么选、怎么做）

**注意**：反常识不能空喊；必须有场景证明，否则打回补证。

---

## 4. 讲故事

**何时用**：人物、客户旅程或团队事件能承载决策冲突；用故事带走启发，再接到成交理由。

**结构骨架**：
1. 人物（谁）
2. 冲突（卡在什么选择 / 怕失去什么）
3. 转折（关键证据或决定出现）
4. 启发（落到可执行标准或低压下一步）

**注意**：故事服务于决策问题；不要为煽情丢掉证据与边界。

---

## 选用提示（内部）

| 更像这个问题 | 优先类型 |
|---|---|
| 不会判断、怕踩坑 | 教知识 |
| 想看怎么做出来的 | 晒过程 |
| 说法对立、要立标准 | 聊观点 |
| 人/事有冲突与转折 | 讲故事 |

类型选定后，再配 1–2 个爆款元素（见 [xuehui-viral-elements.md](xuehui-viral-elements.md)）。
