# 安装后自测用例

安装毕方后，用下面 4 个输入检查是否真的进入毕方逻辑。

## 自测 1：商家自己做内容

输入：

```text
用 bifang-starter 帮我看看：我开社区面馆，想拍抖音引流。先不要写脚本，先判断用户想看什么和今天先拍 3 条。
```

应该看到：

- 先判断用户真正想看的不是“面好吃”，而是“今天值不值得去试”。
- 输出今天先拍 3 条。
- 不直接写完整 60 秒脚本。
- 有“第一条别改丢”的用户问题、判断标准、信任证据、承接动作。

## 自测 2：编导帮客户

输入：

```text
用 bifang-starter 帮我给客户做内容方向判断。

我是短视频编导，客户做全屋定制，目标用户是准备装修的业主，想通过小红书获得私信咨询。客户有工地现场、安装过程和案例照片。

请输出客户能看懂的版本：用户真正想看什么，今天先拍 3 条，第一条别改丢什么。
```

应该看到：

- 识别使用者是编导，目标用户是装修业主。
- 用户判断题应围绕“怎么判断全屋定制不踩坑/怎么相信交付能落地”。
- 给出能转述给客户的解释，而不是只给标题。
- 不把内容改成商家自夸。

## 自测 3：老账号不能当新号

输入：

```text
我的账号发了三个月，有几条播放不错，但私信很少，帮我复盘一下。
```

应该看到：

- 不直接输出新号 3 条选题。
- 先要求提供 9 条历史内容：播放最高 3 条、私信/成交最多 3 条、常发但无效 3 条。
- 引导进入 `bifang-feedback` 或复盘流程。

## 自测 4：模糊需求先澄清

输入：

```text
用 bifang-starter 帮我做一组更高级、更有差异化、更能引流的内容。
```

应该看到：

- 不直接生成一堆“高级感选题”或完整脚本。
- 先把“高级、差异化、引流”翻译成可执行判断：对象、关系、证据、行动。
- 如果信息不足，最多问 1 个关键问题，或标注“基于默认假设”轻跑一版。
- 输出要能看出事实结构：谁在什么场景里，遇到什么问题，看到什么证据，形成什么判断，采取什么行动。

## 不通过时怎么判断

如果输出出现这些情况，说明没有跑到毕方逻辑或提示不够准：

- 一上来直接写完整脚本。
- 只说“多拍探店/多发干货/多做避坑”，没有用户判断题。
- 没有解释为什么先拍。
- 对“高级感/差异化/引流”这类抽象词直接扩写，没有先澄清对象、关系、证据、行动。
- 虚构客户案例、数据、资质。
- 高风险行业承诺结果。

可以用这句话要求重跑：

```text
这版不像毕方。请回到用户判断题：用户为什么看、为什么信、今天先拍什么、第一条改稿不能丢什么。
```
